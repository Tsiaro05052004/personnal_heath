## Décisions

- L'architecture de `docs/architecture.txt` est **validée** (Riverpod, go_router,
  Drift, Supabase) et mise en œuvre étape par étape (section 9).
- Barre du bas : **Accueil, Médicaments, Eau, Carte, Historique**.
  Les **Paramètres** s'ouvrent via l'icône ⚙ en haut (5 onglets maximum).
- Heures de prise stockées en **minutes depuis minuit** (08:00 → 480).
- Chaque table synchronisée a : `id` UUID généré sur le téléphone, `userId`,
  `updatedAt`, `deleted` (suppression logique), `dirty` (à synchroniser).
- Une prise (`IntakeLog`) n'existe que si l'utilisateur a agi :
  statut `taken` ou `missed`. Sans enregistrement = « non confirmée », jamais
  « oubliée » automatiquement. Une seule prise par médicament et par horaire.

## Problèmes rencontrés

- Drift recopie l'expression `clientDefault` dans le code généré : une variable
  privée (`_uuid`) n'y est pas visible → fonction publique `newId()`.
- La contrainte `check()` qui cite sa propre colonne déclenche le lint
  `recursive_getters` → remplacée par `customConstraint('NOT NULL CHECK (...)')`.
